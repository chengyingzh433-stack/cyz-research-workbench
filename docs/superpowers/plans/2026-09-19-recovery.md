# 项目写入保护与任务核实实施计划

主智能体使用 executing-plans 执行。用户已授权继续，不启用子智能体、目标模式或新工作区。

目标：防止两个应用进程写同一项目；异常退出后只读取原有会话核实结果，不自动重新执行。

技术：已有 better-sqlite3、Codex App Server 生成协议、受限 IPC、React 和现有测试工具。不增加依赖。

## 1. 项目锁

- [x] `tests/integration/project-lock.test.ts`：先验证第二进程应被拒绝，原实现实际允许打开，失败已复现。
- [x] `packages/project-service/src/project-lock.ts`：对 `.cyz/write-lock.sqlite` 使用 `BEGIN EXCLUSIVE`，连接存活期间持锁，进程退出由操作系统释放。
- [x] `project.ts`：打开状态库前取得锁，构造失败和关闭时释放。
- [x] `pnpm typecheck` 与 `pnpm test:integration`：31 项通过，包括真实子进程强制退出后再打开。

## 2. 只读恢复核实

文件：新增 `packages/project-service/src/recovery.ts` 与 `tests/integration/recovery.test.ts`；修改 `packages/codex-adapter/src/engine.ts`。

- [ ] 测试：用真实临时项目记录 reconciling 任务，传入运行时终态后应变为 completed；原始运行 ID 保留；重复核实不能重复写消息。
- [ ] 测试：工作目录、threadId 或 turnId 不符时保持未知；没有终态、读取失败、任务未记录会话时不执行新 turn。
- [ ] 实现接口：

```ts
type RuntimeInspection={threadId:string;cwd:string;turns:{id:string;status:string;messages:{id:string;text:string}[]}[]};
type RuntimeReader=(threadId:string)=>Promise<RuntimeInspection>;
// reconcileTask(service, taskId, read) 仅用已登记的 threadId 查询。
// 逐项核对项目运行目录与 turnId；只接受 completed/interrupted/failed。
// 终态、缺失的公开回复与 task.reconciled 事件在同一数据库事务提交。
// 无法确认时返回 {status:'reconciling',reason}，不更改任务、不调用 start。
```

- [ ] `CodexEngine.inspect(threadId)` 调用 `thread/read`，`includeTurns:true`，只映射 turn 状态及 agentMessage，不传出推理项、工具输出、认证字段。
- [ ] 执行专项测试及类型检查。
