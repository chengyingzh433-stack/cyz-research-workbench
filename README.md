# CYZ 研究工作台

这是正在开发的 Windows 桌面工作台，配合 [CYZ 教育研究工作流 0.3.0](https://github.com/chengyingzh433-stack/cyz-edu-research/releases/tag/0.3.0) 使用。当前是开发版本，还没有发布安装包。

## 已经能做什么

- 打开或创建本地研究项目，按 S0–S8 浏览研究阶段。切换阶段不会调用模型。
- 导入材料并保留原件副本。同样内容不会重复登记，同名的不同文件分别保存。
- 编辑工作台草稿，保存历史版本；旧版本可以预览、载入并另存为新版本。
- 编辑既有 `03-文献证据矩阵.md`：标准列用表格和条目表单，复杂内容用源码编辑；周围说明和其他表格保持不变。
- 通过本机 Codex 发起研究对话，显示回复和已知用量，停止运行中的任务。
- 将研究任务放在独立工作副本中。新写的 Markdown 先作为候选成果展示，用户确认后才保存到正式项目。
- 保存前检查版本。如果原稿已被修改，保留双方内容，不直接覆盖。

## 本地启动

开发验证环境是 Windows、Node 24.16.0、pnpm 11.19.0 和 Codex CLI 0.153.4。安装依赖需要联网；首次安装 SQLite 原生依赖可能需要 C++ 构建工具。

```powershell
pnpm install
pnpm build
pnpm start
```

首次打开后，点击“打开或新建项目”。新建项目建议选择一个空文件夹。如果本机已经安装 `cyz-edu-research` Skill，会调用其初始化脚本；这需要 Python 3.11 和 Windows `py` 启动器。

先在“草稿编辑”中保存内容，再发起研究。任务读取项目根目录 Markdown 和已登记的成果版本；材料原件目前只提供目录信息，尚未自动解析全文。不要把“已导入材料”理解成模型已经读过全部论文。

任务结束后，进入“研究成果”查看新增或修改的 Markdown，核对事实、证据和引文，再点击“确认保存为新版本”。仅有对话回答、没有文件变更的任务不会出现候选文件。

## 当前边界

内置 PDF 阅读及定位、MinerU 界面接入、项目备份恢复、本机 Agent API、异常任务的完整处置、安装包和完整研究示例尚未交付。阶段质量仍显示“待核查”，不会把模型执行结束当成研究验收通过。

应用重启后若发现未确认结束的任务，会标记“运行状态待核实”并阻止重复发起。点击“核实任务状态”只读取原会话，确认结束后恢复回复，不重新执行。如果记录缺失或仍在运行，会说明原因并保留未知状态；不要删除状态文件绕过检查。

同一项目以及沿用同一项目 ID 的副本，只允许一个应用进程写入。进程意外退出后，操作系统自动释放写锁。工作副本限制了申请的写入范围，但真实越界写入、交互审批和研究决定卡仍需专项验收。

## 验证

```powershell
pnpm typecheck
pnpm test:unit
pnpm test:integration
pnpm build
pnpm test:e2e
```

`scripts/probe-turn.ts` 和 `scripts/probe-lifecycle.ts` 会真实调用已登录的 Codex，消耗账户额度，不属于离线测试。报告只保留结果，不保留原始对话或认证信息。
